# 기사 피드백(관련 없음 / 도움 됨)

로그인한 사용자가 기사 카드의 작은 두 버튼으로 남기는 신호다. 화면에서 기사를 숨기거나 순서를 바꾸지 않는다(기록만). 나중에 점수·숨김 규칙을 평가하는 자료로 쓴다(`/label/` 라벨과 함께, docs/article-quality-plan.md).

## 구조

- 표 `public.article_feedback`(SQL `supabase/migrations/0006_article_feedback.sql`, 적용 절차 docs/auth-runbook.md 2-5장)

| 열 | 형식 | 뜻 |
|---|---|---|
| `user_id` | uuid, `auth.users` 참조(계정을 지우면 함께 삭제) | 누른 사람 |
| `channel` | text(`^[a-z0-9-]{1,32}$`) | 채널 |
| `article_id` | text(`^[A-Za-z0-9_-]{1,64}$`) | 기사 id. 같은 사건 묶음이면 화면에 보이는 **대표 기사 id** |
| `signal` | `'irrelevant'`(관련 없음) · `'useful'`(도움 됨) | 신호 |
| `created_at` · `updated_at` | timestamptz(서버 시계, 사용자가 보낸 값은 무시) | 처음 누른 시각 · 마지막으로 바꾼 시각 |

- 기본키 `(user_id, channel, article_id)`: 한 사람이 한 기사에 남기는 신호는 하나. 같은 버튼을 다시 누르면 행을 지우고(취소), 반대쪽을 누르면 `signal` 을 바꾼다.
- 사용자당 행 20,000개 상한(서버 트리거, 악용 방지). Realtime 발행에 넣지 않는다.
- 화면은 페이지를 열 때 본인 피드백을 한 번에 읽고(기사마다 따로 요청하지 않음), 누르면 바로 표시한 뒤 서버에 쓰고 실패하면 되돌린다. 표가 없거나 요청이 실패해도 페이지는 그대로 동작한다(버튼 상태만 비어 있음).

## 권한

- 로그인 안 한 요청(anon): 표 권한이 없다(읽기·쓰기 모두 거절).
- 로그인 사용자(authenticated): **본인 행만** 읽기·만들기·고치기·지우기(RLS 작업별 정책 4개). 비밀번호를 바꾼 아이디 계정만(`private.password_ready()`, user_state 와 같음). 다른 사용자의 행은 보이지도 바뀌지도 않고, 남의 `user_id` 로 만들거나 자기 행의 `user_id` 를 바꿀 수 없다.
- 관리자 통계·내보내기: 관리 맥에서 service_role(비밀 키 파일, `~/.heukseok/`)로만 읽는다.
- 검증: `node scripts/admin/users.mjs check`(표 적용·anon 읽기 차단), `node scripts/admin/verify.mjs --apply`(임시 시험 계정 2개로 anon·변경 전·본인·다른 사용자·삭제 시 함께 지워짐까지, docs/auth-runbook.md 4장).

## 가명 내보내기(관리자)

- `node scripts/admin/feedback.mjs stats` — 채널별·신호별 건수, 사용자 수.
- `node scripts/admin/feedback.mjs export [--out <폴더>]` — `[{channel, id, signal, user: "u1", created_at}]`. 사용자는 실행할 때마다 `u1`, `u2` … 로 바꾸고(같은 파일 안에서만 같은 사람이 같은 번호), 아이디·표시 이름·user_id 는 넣지 않는다. 기본 출력 폴더는 `~/.heukseok/feedback-export/`(저장소 밖). 저장소 안에는 쓰지 않는다.
- 내보낸 파일은 개인 기록(누가 어떤 기사를 눌렀는지의 묶음)이므로 저장소·채팅·공개 이슈에 올리지 않는다. 라벨 파일처럼 저장소에 올리려면 사용자 열을 빼고 기사 id·신호만 남긴다.

## 분석할 때의 편향

- **누르지 않은 기사는 '관련 있음'이 아니다.** 대부분의 기사는 아무 신호도 받지 않는다. 신호가 없는 기사는 '모름'으로 다루고, 비율은 '신호를 받은 기사 중' 으로만 말한다.
- **위쪽 기사에 쏠린다.** 사람은 목록 위쪽(새 뉴스·순위순 상위)을 더 많이 보고 누른다. 순위가 낮은 기사의 신호가 적은 것은 덜 봤기 때문일 수 있다. 정렬 방식(순위순·최신순)과 탭에 따라 노출이 달라진다.
- **누르는 사람이 적고 고르다.** 몇 사람이 대부분의 신호를 남길 수 있다. 사용자별 건수를 함께 보고, 한 사람의 취향을 전체 규칙으로 일반화하지 않는다(가명 `user` 열로 확인).
- **'관련 없음'은 숨김 판단의 정답이 아니다.** 이미 본 사건의 중복 보도, 그날의 관심사 등 다른 이유도 섞인다. 규칙을 바꿀 때는 `/label/` 라벨과 교차 검증으로 확인한다(docs/article-quality-plan.md 12장).
- 묶음은 대표 기사 id 에 기록되므로, 묶음 대표가 바뀌면 같은 사건의 신호가 다른 id 에 남을 수 있다(`cluster_id` 로 묶어 본다).
