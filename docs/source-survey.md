# 보험 관련 기관 수집 가능성 조사

조사일 2026-11-05 (KST). **조사 전용** — 운영 collector, `data/`, 사이트에는 연결하지 않았다. 반영은 검토 후 별도 지시.

- 조사 도구: [scripts/probe/](../scripts/probe/) (`probe.py`, `targets.json`), Actions용 [probe.yml](../.github/workflows/probe.yml)(workflow_dispatch 전용, data 커밋·배포 없음).
- 원시 결과: 로컬 보관(저장소에는 포함하지 않음). 측정 환경은 한국 IP(Mac)와 해외 클라우드 IP(Actions 러너, 실행마다 달라짐) 두 곳.
- 방법: 각 게시판 1페이지(필요 시 2~4페이지)만 요청, 요청 간 1.2초 이상, 본문·첨부는 읽지 않음(링크 검증용으로 첫 항목 1건만 열어 상태·제목 포함 여부만 확인). robots.txt 확인. 제목은 현재 `config/categories.json` 규칙으로 분류(규칙 수정 없음).
- **하지 못한 것**: 각 사이트의 이용약관·저작권정책(공공누리 유형 등) 본문은 읽지 않았다. 아래 "위험"은 robots.txt와 접속 특성만 근거다. 반영 전 약관 확인이 필요하다.

## 1. 핵심 결론

1. **금융위 RSS 503은 해외 IP 차단이 아니다(가설 기각).** 한국 IP(Mac)와 Actions(해외) 모두 `fid=0111` RSS는 똑같이 503 `현재 RSS 서비스 점검 중입니다`. 반면 금융위 **보도자료 게시판 HTML(`/no010101`)은 두 곳 모두 200**이고 결과가 동일(40건/4페이지). 즉 RSS 서비스 자체가 점검 중(11/4 첫 확인 이후 이번 조사 시점까지 계속 503)이며, **게시판 HTML 수집이 확실한 대안**이다.
2. 금융위 게시판은 **담당부서 필터가 동작**한다(`?srchKey=dept&srchText=보험과` GET, 또는 POST 폼 — Mac/Actions 동일). 결과 10건이 전부 `보험과`. 링크는 `/no010101/{글번호}`로 영구적이고 상세 200·제목 일치 확인.
3. Mac과 Actions 결과는 사실상 동일. 차이는 2건뿐: 생명보험협회는 Mac에서만 읽기 타임아웃(Actions는 정상), 국민건강보험공단은 Actions 1차 실행에서만 ConnectTimeout(재시도에서 200 — 지역 차단 근거 없음, 일시 오류).
4. **바로 추가할 만한 곳(A)**: 금융위(보험과), 금융감독원, 보험연구원 KIRI 리포트. 나머지는 빈도·관련성·링크 구조 때문에 조건부(B) 또는 제외(C).
5. 현재 분류 규칙은 보험·감독 기관 제목은 비교적 잘 잡지만(금감원 미분류 27%, 금융위 보험과 10%), **통계·보건·국제·연구 기관은 거의 전부 미분류**다. 기관을 추가하려면 분류 규칙이 아니라 "출처 기반 기본 카테고리/키워드 필터"가 필요하다.

## 4. 금융위 RSS 503 대비책

Actions에서도 게시판 HTML이 열리므로 **차단 우회가 필요 없다.** 제안 순서:

1. **게시판 HTML 직접 수집(권장)**: `https://www.fsc.go.kr/no010101` 1~2페이지 + `?srchKey=dept&srchText=보험과`. 공식 구분(source_type=press, feed_name=`금융위원회 게시판`)으로 저장하고, 링크는 `/no010101/{id}` 영구 URL(쿼리스트링 제거). 담당부서 필드로 "보험과"를 걸러 보험 관련 신호만 확보.
2. **RSS 복구 감지**: 기존 `fid=0111` 피드는 그대로 두면 복구 시 자동으로 다시 쓰인다(현재는 상태 페이지에 실패로 표시).
3. **기존 구글 검색 보강 유지**: 금융위 검색 피드는 메뉴 제목 노이즈(`알림마당` 등)가 많았지만 필터가 있으므로 당분간 보조로 둔다. 게시판 수집이 안정화되면 중복을 합쳐 정리.
4. 이용 조건: 담당부서 필터는 정상 사용자 기능(검색 폼)을 그대로 호출하는 것이며, 하루 1회·1.2초 간격이면 부담이 작다. 약관·공공누리 표기는 반영 전 확인.

## 5. 추가 시 collect.py / config 변경 개요 (반영은 별도 지시 후)

- **새 소스 종류 `board`**: `SOURCES` 항목에 HTML 게시판을 추가한다. `probe.py`의 범용 추출기(앵커+같은 행의 날짜, 첨부/다운로드/메뉴 노이즈 제거)를 `collector/boards.py`로 옮기고, 기관별로 `config/boards.json`에 `url`, `method`(GET/POST), `permalink` 템플릿(JS 링크용), `date_precision`(`day`/`month`), `dept_filter`, `max_pages`를 둔다.
- **영구 링크**: 금융위 `/no010101/{id}`, 금감원 `view.do?nttId=…`, 복지부·통계청 `board.es?…list_no`, 협회·개발원·회계기준원은 JS 인자로 템플릿 구성(위 표). 쿼리의 세션·검색 파라미터는 제거해서 ID 안정화(현재 `normalize_url`에 기관별 제거 파라미터 추가).
- **월 단위 날짜(KIRI)**: `published_at`을 월 1일로 저장하되 `date_precision='month'` 표기, 화면은 "10월"로 표시. 새 뉴스는 이미 `collected_at` 기준이라 영향 없음.
- **분류**: 기관 추가 후 미분류 급증을 막으려면 소스별 기본 카테고리/힌트(`feed_hints` 확장: KIRI→보험경영·판매 또는 위험관리, 통계청→사회·인구·기술 변화 등)와 소스별 **키워드 허용 목록**(복지부: 저출산·고령·연금·건강보험 제도, 통계청: 생명표·인구추계·출생·사망, 법제처: 보험·금융위원회 소관, 회계기준원: IFRS17·보험)이 필요하다. 영문(IAIS)은 별도 영문 키워드.
- **상태 페이지**: 기존 `status.json` 구조(소스별 성공/실패, 걸러진 샘플)를 그대로 쓰면 신규 소스도 표시된다. 추출이 0건이면 "구조 변경 의심"으로 실패 처리하는 규칙 필요(범용 추출기라 사이트 개편에 깨질 수 있음).
- **robots/예의**: 기관별 요청 간 ≥1.2초, 하루 1회, 우리 UA 명시. robots 금지 기관(건보공단·한국신용평가)은 제외.
- **중복**: 보도자료는 언론이 다시 쓴 기사와 제목이 달라 URL 기준 중복 제거는 영향 없음. 같은 보도자료를 금융위·금감원이 각각 올리는 경우(예: 계리가정보고서 개정안)는 제목 유사도 병합을 별도로 검토.

## 6. 한계

- 범용 추출기는 사이트 구조 변경에 약하다. 본 조사는 11/5 하루의 스냅샷이며, 빈도(30일 건수)는 1~4페이지 기준 추정이다(MOHW는 페이지 파라미터가 먹지 않아 1페이지 15건 기준).
- JS 렌더링 사이트(한국은행·IFRS·한국기업평가·계리사회·KIF)는 브라우저 자동화나 비공식 내부 API가 필요해 "불가"로 분류했다(로그인·우회·CAPTCHA 회피 없음).
- KIRI 날짜는 월 단위라 probe가 일자를 임의 보정했다(원시 결과의 `2026-10-26`은 신뢰하지 말 것).
