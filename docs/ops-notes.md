# 운영 메모 — 화면에서 뺀 설명

화면 문구 원칙(CLAUDE.md)에 따라 사용자 화면에서 지운 운영·규칙 설명을 여기 모은다. 화면에는 짧은 문구만 남긴다.

## 새 뉴스·읽음

- **새 뉴스 기준**: 마지막 '모두 확인' 이후 **수집된**(collected_at) 기사다. 카드에 보이는 시각은 **발행** 시각(published_at)이라, 늦게 수집된 옛 기사도 새 뉴스에 들어올 수 있다.
- **처음 방문**: 확인 기록이 없으면 보관 중인 기사를 모두 새 뉴스로 보여 준다.
- **읽음 기록**: 제목을 클릭(휠클릭·Enter 포함)해 연 기사와 '읽음' 버튼을 누른 기사가 읽음이 된다. 읽음 기록은 1,500건을 넘으면 오래된 것부터 지우되, 새 뉴스 범위(마지막 확인 이후)의 기록은 우선 보관한다(lib/readState.ts).
- **새 뉴스 건수**: 관련도 낮은 기사와 이미 읽은 기사는 세지 않는다.

## 관련도 낮은 기사

- 제목에 그 채널 관련 단어가 없는 기사(시장 속보·타 업종 등)는 `relevant: false` 로 저장하고 기본 화면에서 숨긴다. 필터의 '관련도 낮은 기사 포함'으로 볼 수 있다.
- 새 뉴스 건수와 이번 주 핵심에는 이 설정과 무관하게 포함하지 않는다.

## 중요도(★)·이번 주 핵심

- 중요도는 제목 키워드로 계산한 값(channels/<채널>/score.json)이라 동점이 많고 정확하지 않을 수 있다.
- 이번 주 핵심은 최근 7일(KST) 발행 기사 중 중요도순 최대 20건이다.

## 감독당국 보도자료 탭

- 금융위원회는 공식 RSS와 게시판 직접 수집, 금융감독원은 게시판 직접 수집이 기본이고 일부는 구글 뉴스 검색으로 보완한다(channels/insurance/feeds.json, boards.json). 검색 보완분은 누락될 수 있다.
- 카드에 표시하던 '공식 RSS'·'검색으로 발견' 수집 경로 표기는 2026-11 화면에서 뺐다(게시판 수집분이 '검색으로 발견'으로 잘못 표시되던 문제 포함). 관련 설정(`channel.json` 의 `notices.press`·`press_discovery_label`)도 삭제했다.

## 키워드 추이

- 기사 제목에 키워드가 들어간 건수를 발행일(KST) 기준 월~일 주 단위로 센다. 이번 주는 진행 중이라 값이 작을 수 있다.
- 키워드는 channels/<채널>/keywords.json 에서 바꾸며, 수집을 실행하면 과거분까지 다시 집계한다. 데이터는 수집을 시작한 주부터 있다.

## 내 데이터(백업·가져오기)

- 가져오기는 기존 기록을 지우지 않고 합친다. 겹치는 북마크·읽음은 하나로, 새 뉴스 확인 시각은 더 늦은 쪽을 쓴다. 합친 뒤에도 읽음 1,500건 한도 규칙을 적용한다.
- '이전 사이트 기록'은 옛 actuary-news-hub 의 localStorage 형식이다(docs/migration-localstorage.md).

## 데이터·링크

- 제목·링크·출처·발행시각과 분류 메타만 저장하고 본문·이미지는 저장하지 않는다.
- 구글 뉴스 경유 링크는 구글을 거쳐 원문으로 이동한다.
- 피드 날짜는 원문 문자열을 먼저 읽고(쉼표 뒤 공백 없음·요일 변형·'GMT+9'·'KST'·'YYYY.MM.DD' 등, collector/dates.py) 못 읽으면 feedparser 값을 쓴다. 그래도 읽지 못한 기사는 저장하지 않고, 소스별 건수를 status.json `skipped.no_date` 와 수집 로그 경고(원문 예시 3개)에 남긴다. 게시판도 날짜 없는 글 수를 같은 곳에 센다.
- 화면 오류 문구는 일반 문장만 보여 주고, 원문 오류(HTTP 상태, 브라우저 영문 메시지)는 브라우저 console 에 남긴다.
- 사이트 빌드 시각·commit 은 /version.json 에서 확인한다.

## 같은 사건 묶기·중요도 v2(품질 플래그)

- 2026-11-12 부터 보험·AI 두 채널 모두 켜져 있다: `channels/<채널>/cluster.json` `enabled`(같은 사건 묶기), `channels/<채널>/score.json` 의 `v2.enabled`(중요도 v2). 켜져 있으면 매 수집 뒤 최근 10일 기사를 다시 판정해 `cluster_*`·`score_v2` 필드를 쓴다. 필드 뜻은 docs/data-contract.md, 설계는 docs/article-quality-plan.md.
- 기존 `score` 는 그대로 함께 저장한다. 화면이 어느 값을 쓰는지는 화면 코드가 정한다.
- **끄는 법(되돌리기)**:
  1. 끄려는 채널의 `cluster.json` 과 `score.json` 의 `v2` 에서 `"enabled": true` 를 `false` 로 바꿔 커밋한다(둘을 함께 끄는 것을 권한다. 묶기만 끄면 이미 저장된 묶음 필드가 2단계 전까지 남아 `score_v2` 가 계속 그 묶음을 쓴다. 2단계는 다섯 필드를 모두 지우고, v2 가 켜져 있으면 다음 수집 때 `score_v2` 만 기사 단위로 다시 생긴다).
  2. 최신 main 을 받은 뒤 저장된 필드를 지운다: `python collector/collect.py --channel <채널> --strip-quality`. `cluster_id`·`cluster_size`·`cluster_sources`·`cluster_lead`·`score_v2` 만 지워지고 월 파일은 필드를 넣기 전과 같은 바이트가 된다(index.json 크기도 다시 맞춤).
  3. `data/<채널>/` 의 바뀐 월 파일과 index.json 을 파일 지정으로 커밋하고 push 한다. 화면은 필드가 없으면 기존 `score` 와 단독 기사로 동작한다.
- 다시 켤 때 과거분까지 묶으려면 플래그를 켠 뒤 `python collector/collect.py --channel <채널> --quality --quality-all` 을 한 번 실행한다. `--dry-run` 을 붙이면 파일을 쓰지 않고 묶음 수·목록 항목 수·★ 분포·일관성 검사만 출력한다.
- 보험 분류 동등성 검사(`scripts/audit/equivalence_collector.py`)는 품질 플래그를 끈 설정 사본으로 새 코드를 돌린다.
