# 디자인 현황 조사와 개선 계획

> 작성 2026-11-11. 조사 전용 문서다(app·components·lib·collector 변경 없음).
> 기준: main `0c89893`, 보험 채널(`/insurance/`). 목표는 '개인 대시보드'에서 '전문적인 뉴스 포털'로 보이게 하는 것이다.
> 측정 방법: 저장소 사본을 빌드해 로컬 정적 서버로 띄우고, Playwright(Chromium)로 1440·768·390px 화면을 캡처했다. 키보드 이동(Tab 32회), 색 대비(WCAG 공식 계산), 네트워크 전송량도 같은 방식으로 쟀다. 캡처 파일은 `/tmp/heukseok-design/shots/` 에만 있고 저장소에는 넣지 않았다.

## 0. 요약

- 접근성 뼈대(`lang`, header/main/footer 랜드마크, 아이콘 버튼 aria-label)는 갖춰져 있다.
- **포털다운 위계가 없다.** 1440×900 첫 화면에 기사가 3건(390×844는 2건)만 보이고, 그 위에 조작 요소가 29개 있다. 모든 기사가 같은 140px 카드다.
- **브랜드 장치가 거의 없다.** 범용 아이콘(lucide `Newspaper`) 하나가 전부이고, favicon·OG 태그·자체 404 페이지도 없다.
- **첫 진입 데이터가 1.31MB**(gzip 약 340KB)다. 이번 달 파일 하나가 1.2MB이고 `cache: 'no-store'` 라 재방문해도 매번 다시 받는다.
- 스타일은 압축된 전역 CSS 한 파일이다. CSS 변수는 3개뿐이고 나머지는 하드코딩이다(색 69종, 글자 크기 13종, 둥글기 15종).

## 3. 화면 문제점(1440 · 768 · 390)

캡처: `/tmp/heukseok-design/shots/{news,week,trends,status,settings,404}-{1440,768,390}.png`, 첫 화면 `news-*-viewport.png`, 상호작용 `news-390-menu.png`·`news-390-filtersheet.png`·`news-1440-dropdown.png`·`news-1440-calendar.png`. 390px에서 문서 전체가 가로로 넘치는 페이지는 없다(탭·칩 줄만 자체 스크롤).

1. **첫 화면 위계**: 헤더 아래 빈 공간이 약 53px이다. 그 뒤로 탭 → 칩 9개 → 검색 → 필터 줄 → 날짜 줄 → 파란 안내 박스 → 목록 머리를 다 지나야 **첫 기사가 y=581(1440) / y=643(390)** 에 나온다. 첫 화면에 기사는 3건/2건이다.
2. **같은 모양의 피드**: 모든 기사가 같은 140px 카드다. 톱기사·섹션·요약 블록이 없어 포털이 아니라 '목록'으로 보인다. 같은 보도를 여러 매체가 낸 비슷한 제목도 줄줄이 반복된다.
3. **내비 이중 구조**: 헤더 메뉴 5개와 본문 탭 4개가 겹친다. aria-label도 "주 메뉴"와 "주요 메뉴"라 구분이 안 된다. 운영 메뉴('수집 상태')와 개인 메뉴('내 데이터'), 운영 정보('마지막 수집' 배지)가 편집 메뉴와 같은 무게로 놓여 있다.
4. **필터 혼잡**: 목록 위 4줄에 조작 요소 29개가 있다. 비활성 '필터 초기화'도 흐리게 항상 보이고, 달력은 인라인으로 펼쳐져 내용을 밀어낸다.
5. **운영자 문구 노출**: "수집시각 기준(표시 시각은 발행시각)", "키워드는 channels/insurance/keywords.json에서 바꾸며…"처럼 설정 파일 경로가 화면에 보인다. 푸터에는 빌드 시각·커밋, "없으면 팀 채널로"가 있다.
6. **브랜드 약함**: 범용 아이콘 로고, 제호 워드마크·오늘 날짜·섹션 구분선이 없다. 사이트 이름(18px)이 목록 머리(18px)와 크기가 같다.
7. **'학습 중요도 ★★☆☆☆'**: 황토색 11px 내부 점수가 모든 카드에 노출된다. 뉴스 포털 톤과 맞지 않는다.
8. **모바일(390)**: 탭·칩 줄이 잘려도 스크롤 단서가 없다. 날짜 버튼·칩은 높이 36px로 터치 권장 44px보다 작다. '필터' 버튼이 거의 전체 폭을 차지하고, 카드 오른쪽 44px 버튼 2개가 제목 폭을 줄인다.
9. **키워드 추이**: 차트 글자가 1440에선 약 15px, 390에선 약 5px(읽을 수 없음)다. 390에서는 표가 세로 카드로 바뀌어 페이지가 4,105px까지 길어진다.
10. **수집 상태**: 34행 표가 390px에서 7,857px다. 일반 사용자에게 필요 없는 운영 화면이 상단 메뉴에 있다.
11. **404**: Next 기본 영어 화면이다. 사이트 톤과 다르고 돌아갈 링크가 없다.
12. **글꼴 혼용**: Arial 숫자와 한글 고딕이 섞여 "2026. 11. 11. 18:20" 같은 줄의 높이·굵기가 어긋난다. 운영체제마다 다르게 보인다.
13. **짧은 페이지**: settings 1440에서 푸터 아래에 회색 띠가 남는다.

- `lib/news.ts:16, 38` 의 `cache: 'no-store'` 때문에 재방문해도 매번 다 받는다. GitHub Pages는 ETag를 주므로 `no-cache`(재검증)로 바꾸면 변경이 없을 때 304로 끝난다.
- status.json(34KB)을 매 페이지 받는다(헤더 배지·푸터·지연 안내). week 페이지도 최근 2개월(1.27MB)을 받는다.
- Next `<Link>` 프리페치로 다른 메뉴 페이지 코드까지 미리 받는다(약 84KB).

### 7.6 제안 순서

1. **헤더 1단계**(H1·H3·H6 + S1·S2·S4, 아래 8장) — 작고, 첫인상 효과가 크고, 기존 기능을 건드리지 않는다.

8. **같은 사건 묶음 표시**(M5) — 수집 쪽 묶음 메타와 함께.

## 9. 결정이 필요한 질문

1. **채널 버튼**: 준비 중 채널(금융·AI)을 '준비 중'으로 미리 보여 줄지, 지금처럼 실제 채널이 2개가 될 때까지 숨길지.
2. **웹폰트**: Pretendard 같은 한글 웹폰트를 쓸지(일관성·인상 개선, 약 300~700KB 부분집합) 아니면 시스템 글꼴을 유지할지.
3. **워드마크 톤**: 신문 제호(세리프·전통적) vs 현대적 고딕. 브랜드 색을 지금 파랑으로 유지할지.
4. **1면 전환 범위**: `/insurance/` 를 1면으로 바꾸고 지금 목록을 '전체 뉴스'로 옮길지, 목록을 유지하고 위에 핵심 블록만 얹을지.
5. **'학습 중요도 ★'**: 그대로 / '중요도'로 이름 변경 / 1면에서는 숨김.
6. **운영 정보 노출**: 수집 상태 페이지·마지막 수집 배지·푸터 빌드 정보를 일반 사용자 화면에서 얼마나 줄일지.
7. **다크모드**: 이번 개선 범위에 넣을지(토큰 선행 필요).
8. **데이터 경량화(P2~P4)**: 수집기와 data 형식을 바꾸는 작업이라 별도 승인 대상. 월말 크기(3MB 추정)를 보고 결정할지, 미리 할지.
9. **화면 확인 방식**: CLAUDE.md는 "화면 검증과 스크린샷은 하지 않는다"이다. 토큰 치환 같은 시각 회귀 확인에 캡처 비교를 허용할지, 사용자가 직접 확인할지.

## 10. 채널은 색과 내용만 바뀌고 틀은 같다(2026-11-12)

보험·AI·금융을 오가도 화면 요소가 같은 자리에 있어야 한다. 측정: `scripts/measure-layout.mjs`(1440·1024·768·390px, 채널 사이 x 차이 1px 이내), 규칙 검사: `tests/channels.test.ts`.

| 채널마다 달라도 되는 것 | 항상 같아야 하는 것 |
|---|---|
| 색(theme.json 4색) | 헤더 메뉴 위치 — 채널 이름 자리는 가장 긴 채널 이름 기준 고정 폭(`lib/channels.ts` `CHANNEL_NAME_WIDTH`, 채널을 더하면 자동으로 맞춰짐) |
| 카테고리 칩(개수·이름) | 탭 줄 — 네 칸 '새 뉴스 · 전체 뉴스 · 공식 발표 · 북마크', 새 뉴스 배지는 고정 최소 폭·고정폭 숫자, 불러오기 전에도 자리를 잡는다 |
| 채널 이름(보험/AI/금융) | 컨테이너 폭 1100px·좌우 여백(넓은 화면 24px, ≤640px 16px — 헤더·채널 이동 줄·본문·홈·마이페이지가 같은 선) |
| 필터 라벨(보험사/기업/금융회사 등)·목록 내용 | 채널 이동 줄 위치와 버튼 크기(선택 상태는 색만 바뀜) |

- 스크롤바: `html{scrollbar-gutter:stable}` — 목록이 짧아 스크롤바가 사라져도 가운데 정렬 화면이 좌우로 움직이지 않는다.
- 글꼴: Pretendard 자체 호스팅(`font-display: swap`). 글꼴이 늦게 와도 채널 이름 자리·탭 배지는 고정 폭이라 오른쪽 요소가 밀리지 않는다.
- 모바일(≤640px): 헤더 메뉴는 햄버거 안 목록(같은 왼쪽 선 16px), 채널 이름 자리는 같은 고정 폭(한글 2자)이라 헤더가 넘치지 않는다.

## 11. '전체 뉴스' 기본 기간은 최근 3일(2026-11-13, 14장으로 대체)

- 옛 보험 사이트는 '전체 뉴스' 기본 날짜가 '오늘'이었으나 의도적으로 '최근 3일(오늘 포함)'로 바꿨다 — 수집이 하루 1회(05:37 KST)라 '오늘'은 아침에 자주 빈 화면이 되기 때문이다. 기본 기간은 칩('날짜 최근 3일')으로 보이되 필터 배지 숫자에는 세지 않고, 필터 초기화는 이 기본값으로 되돌린다(`lib/filterState.ts` `defaultDate`).

## 12. 로그인 화면과 헤더 계정 자리(2026-11-13)

- 스위치(`lib/authConfig.ts`): Supabase URL·publishable 키가 없으면 off — 로그인 코드·장벽·계정 메뉴가 없는 지금 사이트 그대로(보험 동등성 차이 0). 키가 있고 `NEXT_PUBLIC_REQUIRE_LOGIN` 이 꺼져 있으면 헤더에 '로그인' 진입만, 켜면 로그인 화면이 먼저.
- 화면: `/login/`(아이디·비밀번호·아이디 저장), `/login/change-password/`(첫 로그인 강제 변경, 로그아웃만 가능). 둘 다 noindex, 헤더 없이 가운데 카드 하나.
- 헤더 오른쪽 마이페이지 자리가 로그인 뒤 계정 버튼(표시 이름, 최대 200px 말줄임)이 된다. 메뉴: 표시 이름·아이디, 마이페이지, 로그아웃. ≤640px 은 햄버거 안 목록. 오른쪽 끝 고정이라 채널을 바꿔도 다른 요소 위치는 그대로.

## 13. 새 뉴스: 읽음과 치우기를 나눈다(2026-11-13)
- 링크를 열면 '읽음'만 표시한다(모든 탭에서 제목 색을 흐리게 + '읽음'). 새 뉴스 목록에서 사라지지 않으므로 읽은 뒤에도 북마크할 수 있다.
- 목록에서 빼는 것은 새 뉴스 카드의 [치우기](눈 가림 아이콘, 예전 읽음 버튼 자리·크기 그대로)다. 짧게 흐려진 뒤 빠지고 '치웠습니다 [되돌리기]'가 북마크 안내와 같은 자리에 뜬다. 키보드로 치우면 다음 카드의 [치우기]로 포커스가 간다. 같은 사건 카드는 사건째 치운다.
- 필터 패널의 '치운 기사 포함'(새 뉴스 탭에만, 기본 꺼짐)을 켜면 치운 카드가 흐리게 보이고 같은 자리에 [되돌리기]가 붙는다. 켜면 칩·배지, 탭을 옮기면 꺼진다.
- 새 뉴스 건수 = 치우지 않은 새 기사(사건 단위). 북마크와 치우기는 서로 영향이 없다.

## 14. '전체 뉴스' 기간: 기본 제한 없음 + 달력에서 기간 고르기(2026-11-13)
- 모든 탭의 기본은 '기간 제한 없음'이다(숨은 기본 조건이 없어 필터를 다 풀면 항상 전체가 보인다). 기간을 고르면 칩 '기간 11.01~11.10'과 배지 1, 칩 ×·[기간 해제]·필터 초기화는 제한 없음으로.
- 날짜 바: [이전 기간] [달력] [다음 기간] · 오늘 · 3일 · 7일 · 30일 · 이번 달 · [기간 해제]. 달력에서 처음 누른 날이 그 하루(바로 적용)이자 시작, 두 번째로 누른 날까지가 기간이고 기간을 다 고르면 닫힌다.
- 첫 기사~마지막 기사 밖 날짜는 누를 수 없다. 방향키(하루·한 주), PageUp/PageDown(한 달), Enter, Esc(닫고 달력 버튼으로).
- 기간 선택은 다른 필터처럼 화면 상태다(새로고침하면 제한 없음).
- 불러오기: 첫 화면은 지금처럼 최근 2개월. '제한 없음'이면 과거 달을 최근부터 한 달씩 이어 받는다(합계 3MB 안은 자동, 넘으면 목록 끝 페이지에 닿을 때). 기간을 고르면 그 기간에 걸친 달을 받는다(`lib/datePick.ts`).
